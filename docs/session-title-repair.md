# 对话标题规则与旧数据修复方案

## 新对话

- `name` 为空表示没有正式名称。列表、详情和选择器在显示时使用“未命名对话”；未发送的新建界面显示“新建会话”。占位文案不由程序写入名称字段。
- 新建时优先保留 Codex 已有名称。没有名称时，从本次输入的首行有效正文提取最多 28 个 Unicode 字符的初始标题（超过时包含省略号）。去掉常见 Markdown 标记、链接目标，跳过代码块、独立图片、上下文块和裸链接；不调用模型。
- 在创建对话的同一 Codex 连接上调用 `thread/name/set`。成功后保存名称并标记 `title_source=initial`。无可用正文（例如只有图片）时保留空名称。
- 初始命名只执行一次。失败或结果不明确时不阻止首轮运行，显示提示；刷新读取 Codex 的实际结果，后续发送与刷新均不重试自动命名。
- 手动重命名仍先写入 Codex，成功后保存为 `title_source=manual`。用户明确输入的“未命名对话”是合法的手动名称，不能仅按文字判断它是占位。
- 名称不随任务名、项目名、页面入口或后续消息变化。Codex 中后续明确改名可通过新的元数据读取同步回来。

## 来源与并发保护

`sessions.title_source` 为 `initial`（初始短标题）、`manual`（Work Hub 手动名称）、`codex`（Codex 读取/通知的名称）、`legacy`（旧数据，来源不明）或空字符串（无名称）。此来源与现有会话 `source` 不同：后者表示会话来源。

`title_changed_at` 记录名称更新时间。列表、详情和继续运行的元数据读取携带读取开始时间：开始于手动改名之前的响应不能把旧名称写回数据库。空名称响应保留已知名称，相同名称响应保留已有来源。没有版本号的改名通知不能直接替换 `manual` 名称；新的元数据读取仍可发现 Codex 中的后续改名。前端已有历史请求代次保护，防止历史响应覆盖请求途中更新的名称。

新来源和更新时间纳入备份、导入导出；旧备份仍可导入。升级只给旧的非空名称标记 `legacy`，不会仅因名称是“未命名对话”就清空或改名。

Codex 公共改名接口没有按旧名称或版本条件更新的参数。因此跨客户端“检查后、写入前”的竞争无法完全原子化。新建自动命名在返回 Work Hub 创建结果之前执行，后续不自动写名，尽量缩小这个窗口；旧数据修复必须再次核对并跳过状态变化的项目。

## 已有“未命名对话”的修复

以下为待实施方案；此次升级不扫描全文、不批量写入 Codex，也不直接重命名历史对话。

### 1. 先生成只读预览

按运行环境分别处理，在环境内以会话 ID 为唯一标识，候选包括空名称，以及来源为 `legacy` 且名称恰为“未命名对话”的记录。已有 `manual` 名称、正常标题、运行中会话和归档会话默认跳过。

每个候选先用 `thread/read` 核对 Codex 名称。Codex 已有有效名称时，建议动作为“同步已有名称”，无需调用改名接口；Codex 仍无名称时，才分页读取历史，找到最早的有效用户正文，用与新建相同的规则提取短标题。不得使用助手回复、开发者说明、工具输出、图片路径作为标题。历史不完整、无正文、读取失败或只有附件时跳过并记录原因。

预览至少包含：环境、会话 ID、目录、Work Hub 原名称及来源、Codex 当前名称、候选标题、建议动作和跳过原因。只展示命名需要的有限文字，不导出整个对话历史。

旧的 `legacy` 记录不能证明是否由用户手动命名。特别是 Codex 的正式名称也恰为“未命名对话”时，应标为“来源不明，需要人工选择”，不能自动覆盖。

### 2. 选择后再执行

执行前保存 Work Hub 元数据备份和逐条修复清单。仅处理用户选择的候选，并立即重新读取 Codex 和本地名称、来源及更新时间；任一项发生变化、会话开始运行或归档时跳过。

- “同步已有名称”：只更新 Work Hub 索引。
- “补初始标题”：仅在 Codex 仍无名称时调用 `thread/name/set`，确认成功后写入 Work Hub 并标记 `initial`。
- “来源不明”：只有用户逐条明确选择后才改名。

每个写入记录环境、会话 ID、执行前实际名称、新名称、状态和错误。结果不明确时标记“待核对”，禁止盲目重发；下次只读取 Codex 确认实际结果。修复标题不调用 `turn/start`、不增加消息、不恢复归档、不移动目录。

### 3. 验证和回退

执行后重新读取 Codex，核对列表与详情名称。重复预览应不再列出已修复项。

回退必须通过 Codex 的公共改名接口，并先确认当前名称仍是本次修复写入的值；若用户之后又改过名，则跳过。仅恢复 Work Hub 数据库备份无法撤销 Codex 中的名称。原名为空时，先验证所用 Codex 版本是否支持清除名称；不支持时不能承诺自动恢复为空，应保留修复清单供手动处理。
